## The plot index is built from the five galleries (ticket 48, criterion 5)

`wayline.figures.build_index` ran on 2026-09-12 against the live python-graph-gallery, r-graph-gallery, Altair, seaborn, and plotnine sites, through a caching fetcher (`research/.cache/figures/`), from the harness worktree `.claude/worktrees/ticket-48-plot-index`. Following research-notes 09's own precedent of a bounded page sample per site for a live check ("No more than ten pages were fetched per site"), this run capped each site at 15 chart pages (`max_pages_per_site=15`) rather than crawling every page the five sites list; the offline suite (`tests/test_figures.py`) separately exercises the full, uncapped code path against six recorded pages spanning all five sites. A build with no cap is `wayline figures build-index`'s default and is what a project actually runs.

`figures/plot_index.json` for this run is 97,352 bytes for 75 entries (about 1.3 KB/entry). The crawl took 909.8 seconds end to end; the seam's 1 request/second limit accounts for under 80 seconds of that, so the rest is the five sites' own response time for full gallery pages (several sampled pages ran 300-900 KB of HTML), not the rate limiter — a fact this note adds since research-notes 09 measured page counts and licensing but not per-page transfer time.

### What the crawl found

Family classification across the 75 entries: `multi_dimensional` 26, `distribution` 18, `ranking` 17, `evolution` 5, `correlation` 5, `part_of_a_whole` 3, `map` 1 (`network` and `flow` had no representative among the pages sampled this run — plausible, since none of the five galleries' first pages in crawl order happened to be a network or flow diagram). Library detection: `seaborn` 23 (including python-graph-gallery pages whose code the site itself renders in seaborn), `ggplot2` 15, `altair` 15, `plotnine` 15, `matplotlib` 7. 7 of the 75 entries carry seeded `known_pitfalls` — every entry whose detected library is matplotlib, per research-notes 11 Section 2's classification table.

### What differed from the research notes

1. **python-graph-gallery mixes matplotlib and seaborn page by page**, not gallery-wide as research-notes 09's single "matplotlib" default library might suggest; of the pages sampled here, seaborn calls outnumbered matplotlib calls, so `build_index` detects the actual library per page from its code (`sns.` versus `plt.` call sites) rather than trusting the site's default.
2. **plotnine's own gallery code is syntactically identical to ggplot2's** (`ggplot() + geom_*()`), so a call-site pattern cannot tell the two libraries apart; only the site a page was fetched from can, and `build_index` relies on that rather than on a marker in the page.
3. **A syntax-highlighted code block wraps every token, including a lone `.`, in its own tag** (seaborn's and plotnine's Sphinx/Quarto themes both do this), so `sns.violinplot` appears in the raw HTML as three separate tagged text nodes; a raw-HTML regex search for `sns\.\w+` never matches. `build_index` searches the tag-stripped page text instead.
4. **A plain substring search for a family keyword misreads "map" out of "heatmap"**; the classifier excludes that one case with a negative lookbehind rather than requiring whole-word matches everywhere, since a whole-word rule breaks the equally common single-word compounds ("scatterplot", "boxplot", "barplot") these galleries use.
5. **A full, uncapped crawl of all five sites is a multi-hour live run at these sites' per-page response times**, not the few-minutes estimate research-notes 09's index-page-only fetch implied; a project running `wayline figures build-index` for the first time should expect this, and `wayline figures refresh` (liveness only, one request per stored `source_url`) is the cheap path for routine upkeep.

### The recorded responses

`fixtures/fetch/` gained recordings for `python-graph-gallery.com`, `r-graph-gallery.com`, `altair-viz.github.io`, `seaborn.pydata.org`, and `plotnine.org` (11 files total: one index or sitemap fetch per site, one chart page per site, plus a second python-graph-gallery page chosen to exercise the matplotlib pitfall seeding), recorded 2026-09-12. `fixtures/fetch/README.md` is how to remake them; the hash leaves out the `User-Agent`, so these recordings replay for any owner.

### What differed from the research notes

1. **Four venues refuse a stateless client outright.** Cell, Cell Systems, PNAS and Bioinformatics answer the harness's `urllib` request with HTTP 403 from a bot check, on every path tried. The note reached three of those four through a browser-shaped fallback tool that the harness does not have and, under Implementation Decisions 1, will not grow. Their fields are the note's and stay unverified until something reaches them, which is why the build's verification is stricter than the note's and not a regression against it.
2. **Genome Biology, which the note could not reach at all, now answers.** The note's action item was to retry by another path; the retry is what the build does, and BMC has since moved its journals onto Springer Nature Link, where `journal/13059/submission-guidelines/research` is public. Five of its eight fields moved from "unverified, page behind a login" to read off a fetched page: the 250-word abstract cap, the section list down to the Declarations subheadings, the Vancouver reference style, and the BioMed Central Minimum Standards of Reporting Checklist. This is the one venue where the build knows more than the note did.
3. **Nature writes "4300 words", not "4,300".** The note recorded a thousands separator the page does not use. The evidence string is the page's spelling, and this is exactly the class of drift the evidence check exists to catch: a marker taken from a summary rather than from the page fails on the first build.
4. **nature.com serves the page behind a cookie-consent redirect.** Every nature.com URL comes back 200 with `?error=cookies_not_supported` appended, carrying the real guide. The note called this a bot check rather than an auth wall and it is: the words are all there.
5. **Nature Communications keeps its numbers in a PDF.** The guide-to-authors page is prose; the word count, the display-item cap, the 300 dpi and the 350-word legend cap are in the submission-guide PDF it links. Nothing in the harness reads inside a PDF, so six of that venue's eight fields stay unverified however well the note read them. It is the one venue where the build reaches the page and still cannot confirm most of what is recorded.
6. **ICML splits its page limit across two pages.** The call for papers gives the eight-page submission limit and the author instructions the nine-page camera-ready limit, so both are fetched and both are evidence.
7. **The conference style packages are not document classes.** NeurIPS, ICML and ICLR ship a `.sty` a draft loads with `\usepackage`, not a class. `template.document_class` holds the name either way and the conformance check looks for both spellings; the names themselves follow each conference's convention rather than a statement on the page, so all three are unverified.

### What was cached, and what was not

Four reporting-checklist forms were fetched and cached, all without a login: the Nature Portfolio Reporting Summary into `guidelines/nature/`, `guidelines/nature-methods/` and `guidelines/nature-communications/` (the same 437 KB form, once per venue, so each venue directory stands on its own), and eLife's MDAR checklist into `guidelines/elife/`. Nature Methods caches the form its record says it needs while `reporting_checklists` stays unverified for that journal, because no nmeth-specific page saying so was reached.

No manuscript template was fetched or stored. `template.url` is a link in every one of the fifteen files, and a test asserts that no URL named there was ever requested and that nothing under `guidelines/` is a `.zip`, `.docx`, `.cls`, `.sty` or `.tex`.

## One toy result becomes a ranked, checked, and verdicted figure (ticket 50, criterion 5)

`wayline figure make` ran on 2026-09-23 from the harness worktree `.claude/worktrees/figure-role-pipeline`. It ran against `~/wayline-m7/toy`, a copy of the M5 toy project (`~/wayline-m5/toy`). The copy has the M5 night's results, manifest, and `harness.json`, with autonomy `autonomous` and the fallback consent `auto`.

### The plot index it drew from

`wayline.figures.build_index` crawled the five live galleries into the copy's `figures/plot_index.json`, at 15 chart pages per site as ticket 48's live run did. It took 683 s for 75 entries: `multi_dimensional` 25, `distribution` 18, `ranking` 17, `evolution` 6, `correlation` 5, `part_of_a_whole` 3, and `map` 1.

### The request

The figure carries the E1 claim at signal 4.0. Adding x3·x4 lifts held-out AUROC over the raw features on every one of ten seeds and matches adding all pairs, while the wrong pair x1·x2 adds nothing.

- **Data:** one file, `analysis/ablation/signal-4.json`, manifested to run `t36-a1`.
- **Target:** 89 mm wide, at most 110 mm tall, 6 pt minimum, 300 dpi, PDF and PNG, drawn in matplotlib.
- **Budget:** at most 4 candidates, 1 critic session, and 2 verifier sessions.

The request is `~/wayline-m7/request-e1.json`.

### What each step did

1. **The shape, in code.** The classifier took the biggest table in the nested analysis record: the `auroc` block, 10 rows (seeds) by 4 numeric columns (arms). The families were `ranking` and `distribution` from the `comparison` claim, then `correlation` from the shape.
2. **The candidates, one family at a time.** They came from the index:
   - `horizontal-barplot-python-graph-gallery` (ranking);
   - `basic-2d-histograms-with-matplotlib-python-graph-gallery` (distribution);
   - `scatter-point-paths-hover-altair` (correlation), which the index implements in Altair and the designer drew in matplotlib;
   - `control-color-of-barplots-python-graph-gallery` (ranking).
   
   Each carried the five seeded matplotlib pitfalls, and every draft listed all five in `pitfalls_consulted`.
3. **Drafts.** One `figure-designer` session on `claude-opus-5-5`, `high`, rendered all four from the real data.
4. **The ranking.** A fresh `figure-critic` session on `claude-opus-5-5` ranked them:

   | Rank | Draft | Legibility of the claim | Honesty | Venue fit | Legibility at size | Total |
   |---|---|---|---|---|---|---|
   | 1 | control-color-of-barplots | 5 | 5 | 4 | 4 | 18 |
   | 2 | horizontal-barplot | 4 | 4 | 5 | 4 | 17 |
   | 3 | scatter-point-paths-hover | 4 | 5 | 3 | 4 | 16 |
   | 4 | basic-2d-histograms | 2 | 4 | 2 | 3 | 11 |

   Rank 1 won because it was "the only draft that plots the quantity the claim is about, the same-seed change over raw".
5. **The pick.** Under `autonomous`, the decider's rule took rank 1 with `margin: 1` and `margin_low: true`, below `figures.margin_threshold` 2.
6. **The finish.** A fresh designer session added panel (a), the absolute AUROC per arm, which answered the critic's one lost point. Panel (b) is the same-seed change as open bars with every seed drawn. It wrote the caption and a notes file with the measurements behind each choice.
7. **The checks and their one repair.** The first check run failed `min_font_pt`: 4.90 pt in the PDF text walk against 6.50 pt in the artist report. Mathtext set the subscripts of `$x_1x_2$` at 70% of 7 pt. This is the blind spot between the two readers that ticket 49 built both for. The one repair switched to Unicode subscript digits, and all 19 checks passed, with crops `a.png` and `b.png`.
8. **The honesty verdict.** It went through the gate on `claude-fable-5-1`, `high`, the table's verifier for an Opus author, and passed with two minor findings:
   - The headline states "as much as adding all pairs" and "does not" as verdicts. The analysis gives both differences only as intervals that include zero (all pairs minus x3·x4: −0.0002, ci95 [−0.0008, 0.0003]). This is an overstatement of certainty, not a false claim, since the caption's own panel (b) text hedges x1·x2 as "indistinguishable from zero".
   - The read-only verifier could not recompute the data file's hash. The `provenance` check had already done so.

   The figure passed no equation to verify, so no sub-verdict ran.

The result is `verified`, version 1. `figure_result` was journaled with its path and hash, and the final figure is `docs/verification/images/50/e1-signal4.png`.

### What left the role

- **Proposals.** The three `findings_for_text` became proposals, and admission took all three as `writing` tickets 57, 58, and 59 in the copy:
  - report the all-pairs-minus-x3·x4 estimate with its interval, not a tested match;
  - write "no change distinguishable from zero" for the wrong pair, not a tested null;
  - report the absolute levels beside the paired gain.
  
  The first two are the honesty verdict's own minor finding, reached independently by the designer.
- **Traps.** The designer recorded four `traps_hit`, three of them promoted:
  - the cross-library Altair candidate;
  - alpha-blended bar fills that leave the palette;
  - the mathtext subscript size.
  
  They were filed as one `feedback` item with source `figure` for the evolve loop. `wayline figures fold-traps figures/e1-signal4/figure_result.json` folded 2 of the 3 into the index entries they name. The Altair trap was left out because the designer paraphrased its chart type ("scatter with point paths (hover + search box)") rather than copying the index's. The designer's protocol now requires the chart type verbatim.

### What differed from the research notes

1. **The index's menu is thin for a paired, per-seed comparison.** None of the 75 sampled entries is a strip plot or a paired-difference plot. The candidates were two bar charts, a 2D histogram, and a cross-library scatter. The figure came out right because the critic ranked by the claim and the finishing session redrew the chosen bar chart around it. The index supplied a starting shape, not the answer. A fuller crawl (every page, not 15 per site) is the remedy research-notes 09 already names.
2. **The shape classifier cannot see pairing across columns.** The arms are columns and the seeds are rows, so "paired by seed" is structure the file does not declare. The claim type, not the shape, is what put `ranking` and `distribution` first. That is why `_families` now ranks the claim's families ahead of the shape's where they disagree.
3. **The ranking is not a pick.** The decider's rule took rank 1 by one point, flagged `margin_low`, so the owner's dashboard shows the alternatives. Research-notes 11 Section 4.1 expected exactly this use of the flag.
