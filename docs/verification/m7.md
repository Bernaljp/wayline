## The plot index is built from the five galleries (ticket 48, criterion 5)

`wayline.figures.build_index` ran on 2026-09-12 against the live python-graph-gallery, r-graph-gallery, Altair, seaborn, and plotnine sites, through a caching fetcher (`research/.cache/figures/`), from the harness worktree `.claude/worktrees/ticket-48-plot-index`. Following research-notes 09's own precedent of a bounded page sample per site for a live check ("No more than ten pages were fetched per site"), this run capped each site at 15 chart pages (`max_pages_per_site=15`) rather than crawling every page the five sites list; the offline suite (`tests/test_figures.py`) separately exercises the full, uncapped code path against six recorded pages spanning all five sites. A build with no cap is `wayline figures build-index`'s default and is what a project actually runs.

The crawl took 909.8 seconds end to end; the seam's 1 request/second limit accounts for under 80 seconds of that, so the rest is the five sites' own response time for full gallery pages (several sampled pages ran 300-900 KB of HTML), not the rate limiter — a fact this note adds since research-notes 09 measured page counts and licensing but not per-page transfer time.

### What the crawl found

Family classification across the 75 entries: `multi_dimensional` 26, `distribution` 18, `ranking` 17, `evolution` 5, `correlation` 5, `part_of_a_whole` 3, `map` 1 (`network` and `flow` had no representative among the pages sampled this run — plausible, since none of the five galleries' first pages in crawl order happened to be a network or flow diagram). Library detection: `seaborn` 23 (including python-graph-gallery pages whose code the site itself renders in seaborn), `ggplot2` 15, `altair` 15, `plotnine` 15, `matplotlib` 7. 7 of the 75 entries carry seeded `known_pitfalls` — every entry whose detected library is matplotlib, per research-notes 11 Section 2's classification table.

### What differed from the research notes

1. **python-graph-gallery mixes matplotlib and seaborn page by page**, not gallery-wide as research-notes 09's single "matplotlib" default library might suggest; of the pages sampled here, seaborn calls outnumbered matplotlib calls, so `build_index` detects the actual library per page from its code (`sns.` versus `plt.` call sites) rather than trusting the site's default.
2. **plotnine's own gallery code is syntactically identical to ggplot2's** (`ggplot() + geom_*()`), so a call-site pattern cannot tell the two libraries apart; only the site a page was fetched from can, and `build_index` relies on that rather than on a marker in the page.
3. **A syntax-highlighted code block wraps every token, including a lone `.`, in its own tag** (seaborn's and plotnine's Sphinx/Quarto themes both do this), so `sns.violinplot` appears in the raw HTML as three separate tagged text nodes; a raw-HTML regex search for `sns\.\w+` never matches. `build_index` searches the tag-stripped page text instead.
4. **A plain substring search for a family keyword misreads "map" out of "heatmap"**; the classifier excludes that one case with a negative lookbehind rather than requiring whole-word matches everywhere, since a whole-word rule breaks the equally common single-word compounds ("scatterplot", "boxplot", "barplot") these galleries use.
5. **A full, uncapped crawl of all five sites is a multi-hour live run at these sites' per-page response times**, not the few-minutes estimate research-notes 09's index-page-only fetch implied; a project running `wayline figures build-index` for the first time should expect this, and `wayline figures refresh` (liveness only, one request per stored `source_url`) is the cheap path for routine upkeep.

### What differed from the research notes

1. **Four venues refuse a stateless client outright.** Cell, Cell Systems, PNAS and Bioinformatics answer the harness's `urllib` request with HTTP 403 from a bot check, on every path tried. The note reached three of those four through a browser-shaped fallback tool that the harness does not have and, under Implementation Decisions 1, will not grow. Their fields are the note's and stay unverified until something reaches them, which is why the build's verification is stricter than the note's and not a regression against it.
2. **Genome Biology, which the note could not reach at all, now answers.** The note's action item was to retry by another path; the retry is what the build does, and BMC has since moved its journals onto Springer Nature Link, where `journal/13059/submission-guidelines/research` is public. Five of its eight fields moved from "unverified, page behind a login" to read off a fetched page: the 250-word abstract cap, the section list down to the Declarations subheadings, the Vancouver reference style, and the BioMed Central Minimum Standards of Reporting Checklist. This is the one venue where the build knows more than the note did.
3. **Nature writes "4300 words", not "4,300".** The note recorded a thousands separator the page does not use. The evidence string is the page's spelling, and this is exactly the class of drift the evidence check exists to catch: a marker taken from a summary rather than from the page fails on the first build.
4. **nature.com serves the page behind a cookie-consent redirect.** Every nature.com URL comes back 200 with `?error=cookies_not_supported` appended, carrying the real guide. The note called this a bot check rather than an auth wall and it is: the words are all there.
5. **Nature Communications keeps its numbers in a PDF.** The guide-to-authors page is prose; the word count, the display-item cap, the 300 dpi and the 350-word legend cap are in the submission-guide PDF it links. Nothing in the harness reads inside a PDF, so six of that venue's eight fields stay unverified however well the note read them. It is the one venue where the build reaches the page and still cannot confirm most of what is recorded.
6. **ICML splits its page limit across two pages.** The call for papers gives the eight-page submission limit and the author instructions the nine-page camera-ready limit, so both are fetched and both are evidence.
7. **The conference style packages are not document classes.** NeurIPS, ICML and ICLR ship a `.sty` a draft loads with `\usepackage`, not a class. `template.document_class` holds the name either way and the conformance check looks for both spellings; the names themselves follow each conference's convention rather than a statement on the page, so all three are unverified.

### What was cached, and what was not

Four reporting-checklist forms were fetched and cached, all without a login: the Nature Portfolio Reporting Summary into `guidelines/nature/`, `guidelines/nature-methods/` and `guidelines/nature-communications/` (the same 437 KB form, once per venue, so each venue directory stands on its own), and eLife's MDAR checklist into `guidelines/elife/`. Nature Methods caches the form its record says it needs while `reporting_checklists` stays unverified for that journal, because no nmeth-specific page saying so was reached.

No manuscript template was fetched or stored. `template.url` is a link in every one of the fifteen files, and a test asserts that no URL named there was ever requested and that nothing under `guidelines/` is a `.zip`, `.docx`, `.cls`, `.sty` or `.tex`.

### The recorded responses

The same run, repeated through the recording backend, left 28 responses under `fixtures/fetch/`, 1.69 MB, one file per distinct request: the 31 requests include the Nature Reporting Summary three times, once per venue that carries it, and a repeated request is one recording. The build asks for `Accept-Encoding: gzip` and the recordings hold the compressed bodies: the fifteen venues' pages are about 800 KB recorded against roughly 2.5 MB raw, and the two checklist PDFs are the rest. `fixtures/fetch/README.md` is how to remake them.

## The seven mechanical checks run on a draft (ticket 52, criterion 3)

The checks need no network and no live record, so the suite is the whole of their verification: `fixtures/manuscripts/markdown-draft/` and `fixtures/manuscripts/latex-draft/` are run against two venues each, and the interesting assertion is that one draft draws different verdicts from different guidelines. The Markdown draft's 72 dpi PNG fails PLOS Computational Biology's figure spec on both format and resolution and passes Nature, which names neither; its missing Reporting Summary fails Nature and not PLOS, which asks for ARRIVE instead and finds it; its missing author block fails PLOS's section list and is only a warning under Nature's, which is structure-flexible. The LaTeX draft loads ICLR's style package, so it passes ICLR's template check and fails ICML's, and its three-page compiled PDF is read for the page count that neither venue's limit would otherwise be checkable against.
