### The answer: the format and the runner contract

The format is the one research note 07 proposed and Implementation Decisions 12 adopted, now a
schema (`schemas/fixture.json`) and a runner (`wayline/fixtures.py`). What the prototype question
left open, and what the implementation settled:

- **How a change reaches a pinned input.** A fixture pins the prompt, the `--agents` JSON, the
  schema, and the context, so a change to the subject has to be put back into that pack before
  each run. Each subject file gets one route: a role's `agent.md` becomes the `--agents` description
  and prompt; a schema under `schemas/` replaces the pinned `--json-schema`; a skill's directory is
  delivered into the run's project as `.claude/skills/<name>/`; any other file is pinned under
  `input/subject/` and replaced where its text sits in `input/prompt.md`. A subject that none of
  these carries is refused, both when recording and when running, because a fixture that silently
  ran the old subject would pass forever.
- **Where a subject runs.** In a fresh project under `~/.wayline/fixture-cache/subject/<key>/<sample>/<n>/project`,
  holding `input/context/`, with the recorded launch replayed through the worker launcher and the
  recording machine's paths templated as `{harness}`, `{project}`, and `{run}`. A ticket's run is a
  git repository with the input committed on `main` and checked out on `ticket/<id>`.
- **What the runner keeps in `fixture.json`.** `last_run` (the hashes, the definition hash, and the
  outcome per layer) is what a flake is measured against: a different outcome with the subject and
  input hashes unchanged is a flake. A change to the checks, the judged layer, the rubric, or the
  input is a rewrite, which restores the fixture and resets its baseline. `quarantine.counted_from`
  keeps the flakes before a restore without counting them again. `runs/` is per-machine output and
  is not committed.
- **Exit codes.** 1 when a fixture that passed at its baseline fails now and is not quarantined,
  including one that can no longer be loaded, rendered, or launched; 2 when the suite stopped for
  cost (the turn ceiling, which skips only the judge, a usage window that refused a session, or a
  second full suite in one weekly window); 0 otherwise.

- The conductor, not you, decides when a ticket is done: it runs the acceptance again after you

### The answer

Does the fixture format catch a regression? Yes, with two conditions that the runs above made
concrete:

- The regression has to change what the fixture pins. Two edits that contradicted the ticket's
  explicit steps (runs c and c2) changed no behavior and correctly did not fail. The edit that
  changed a decision the ticket leaves to the role (run c3) failed the structural layer and exited 1.
- One sample is not enough. The breaking edit showed in one coder session of three. Structural
  checks held to n of n over three samples caught it, and one sample would have caught it a third of
  the time.

It held stable across two full runs (a2 and b, twelve sessions, no flake). It set its baseline only
after the recorder flagged the first one unstable and the rubric was rewritten. It cost 43 + 6 + 40
turns to establish, 39 + 41 + 31 to break three times, and nothing to check again from the cache.
The format of Implementation Decisions 12 stands as specified. The runner contract adds the four
readings recorded under "The answer: the format and the runner contract" above.

Total live spend for this record, from the runner's own cost lines: 256 turns across the recording
(56, in the environment that denied every write) and runs a to e, all on the subscription and none
with `--bare`.

### The suite offline and under a minute (criterion 4)

Before this ticket, `python -m unittest` took 400 s on this machine (3105 tests, serial). Its slowest test waited
out the shipped 60 s `poll_seconds` between two waves. Three changes brought it down:
- **Forked workers.** `tests/__init__.py` now runs the package's suite in forked children, one test class each,
  the largest first. `WAYLINE_TEST_JOBS=1` runs it serially, and a module named on the command line is never
  forked.
- **The flag.** It sets `WAYLINE_BACKENDS=none`. Under it:
  - the installed `claude` executable and the real network raise `BackendTouched` if reached;
  - the converter install raises before it downloads;
  - the GPU probe reads a machine with no GPU without running `nvidia-smi`;
  - `ruff` through `uvx` runs from its cache (`f052b6c`, found by the offline run below).
- **The slow test.** The 60 s test now sets `poll_seconds` to 1.

The run with the backends really unavailable used `unshare -rn`, which is refused on this machine ("Permission
denied"), so it did this instead:
- put stubs of `claude` and `nvidia-smi` first on `PATH`, each logging "backend touched" and exiting 99;
- put a `sitecustomize` on `PYTHONPATH` that refuses and logs any non-loopback connect or DNS lookup in every
  Python process;
- pointed the proxies at a dead port;
- set `CUDA_VISIBLE_DEVICES` empty.

On this branch's last code:
