### Two facts about `dontAsk` that the role's tool list does not carry on its own

**An unallowlisted Bash command runs when it only reads.** Verdict 1's session ran
`grep -qx 'alpha extended' notes/alpha.md; od -c notes/alpha.md`, and verdicts 3 and 4 ran
`cat -A notes/alpha.md`. Neither `grep`, `od`, nor `cat -A` is covered by a
`Bash(...)` rule in `roles/verifier/wayline.json`, `permission_denials` was empty, and the output
came back. `docs/verification/m0.md` records the opposite outcome for the coder, where
`mkdir -p m0 && printf ... >> ...` was refused with `decision_reason_type: "mode"`. The
difference is what the command does, not whether a rule names it.

**A Bash command that writes is refused, inside the project and with no rule against it.** One
cheap `sonnet low` probe session on the verifier role was asked to attempt four things in order
and to report each outcome. `cat notes/alpha.md` and `wc -l notes/alpha.md` ran; `printf 'probe\n'
> notes/probe.txt` was refused, with `decision_reason_type: "subcommandResults"` and the message
"Permission to use Bash with command printf 'probe\n' > notes/probe.txt has been denied"; the
`Write` tool was not in the session's tool list at all. Neither file exists on disk. So the
verifier is read-only live, and the layer that makes it so is the permission system's own reading
of the command, with the absent write tools behind it, not the `Bash(...)` allowlist.

**The verifier's tool list is exactly five tools.** Read off `system/init` rather than guessed at:
`Bash, Glob, Grep, Read, StructuredOutput`. Verdicts 1 and 2 and the first probe showed a sixth,
`ToolSearch`, which was on neither of the role's lists and which exists to fetch the schemas of
deferred host tools; it is now in `disallowed_tools`, and verdicts 3 and 4 are with it there. The
coder's list does not name it either, and nothing here shows whether a tool fetched that way
would reach past `--disallowedTools`. That is a question for the guards (OPEN-5, OPEN-7), not an
answer this run has.

**Ten host tools did not reach the verifier.** `docs/verification/m0.md` records the coder's live
session inheriting ten tools from the owner's own configuration, because `--settings` adds to it
rather than replacing it. None of them is in the list above, so the role's denylist, which names
all ten, held.

The five-hour window's `rate_limit_event` arrived as `status: allowed` with `unifiedWindows`
present, as in M0 and M3; no verdict came near a limit.
