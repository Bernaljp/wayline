# Map: the wayline harness (SpecDrivenResearch)

Label: wayfinder:map
Tracker: local markdown (this directory is not a git repository; tickets are the files under `issues/`, research notes land in `../../research-notes/`)
Charted: 2026-09-11. Map complete 2026-09-11: no open tickets; hand off to to-spec, then to-tickets, in one session.

## Destination

A harness (name to be chosen) that turns a research intent of any specificity, optionally with a quantitative goal, into a finished report (references absorbed to the depth they deserve, positioned idea, spec, ticket graph, implemented and documented code, experiments run on this workstation's GPUs and CPUs, verified results, every claim traced to a result or a reference), running only on the owner's Claude Code subscription across usage windows, with deterministic code deciding what runs and when, and models deciding only content. It pauses on decision tickets the owner answers, continues to a paper for a chosen journal on request, and improves itself from the owner's feedback through tested, versioned changes. It serves a local dashboard (a tab per project, an outputs index with downloads, decision answers and controls) reached from a laptop through a tunnel to the workstation.

The map is done when M0 to M7 in BRIEF.md Section 16 can be written as tracer-bullet tickets.

## Notes

- **Primary reference:** `BRIEF.md` (revision 2). Its DECIDED items and hard constraints C1 to C10 are settled and are not re-opened here. Its Section 15 OPEN decisions are this map's tickets, in order; each ticket carries the brief's recommended answer as the default.
- **Standing preferences:** the owner accepts the recommended answers as defaults and wants decisions made for them; facts are looked up (installed CLI, official docs, this machine) and never asked; American English, no em dashes, in every artifact.
- **Skills every session consults:** `grilling` and `domain-modeling` for grilling tickets (the glossary is `CONTEXT.md` at the repo root, seeded from BRIEF.md Appendix D); `research` for research tickets (notes go to `research-notes/NN-slug.md`); `prototype` for prototype tickets (throwaway code under `.scratch/proto/<name>/`, never in the harness tree). The owner's `paper-figures` skill is read critically as inspiration only.
- **Verified environment (2026-09-11):** Claude Code 2.1.268; flags of note for this effort: `--agents`, `--agent`, `--json-schema`, `--permission-mode dontAsk`, `--permission-prompts none`, `--settings`, `--setting-sources`, `--allowedTools`, `--tools`, `--restricted`, `--bg`, `--resume`, `--session-id`, `--fallback-model`, `--effort`, `--autocompact`, `--system-prompt-snapshot`, `--no-session-persistence`; subcommands `agents`, `logs`, `stop`, `rm`, `setup-token`. Machine: one NVIDIA RTX 3090 (24 GB), 128 cores, 1 TB RAM, 11 TB disk; Ubuntu with systemd 255, user lingering enabled, cron in use by another project; Python 3.12.3, Node 22.22.3, git 2.43; `pdftotext`, `notify-send`, `tmux`, `codex` present. The statusline script already reads `rate_limits.five_hour` and `rate_limits.seven_day` from Claude Code's statusline JSON.
- **Batch confirmations (override of the one-ticket-per-session rule):** a grilling ticket whose Question states a default and has no unresolved blockers may be confirmed or overturned in a single round together with the other such tickets. One session may resolve all of them at once: claim each, ask the whole batch as one grilling round with the default as the recommended answer, record each answer in its own ticket, close each, and add one Decisions-so-far line per ticket. Batchable: Consultant invocation shape (graduated from fog after OPEN-1). Tickets whose Question depends on a prototype (OPEN-5, OPEN-15, OPEN-16, OPEN-17, OPEN-20) and every prototype ticket stay one per session.
- **Ticket order:** research tickets 01 to 11 are AFK and were fired at charting. Decisions follow the brief's OPEN-1 to OPEN-21 order; prototypes sit just before the decision they inform.

## Out of scope

Ruled beyond this map's destination; returns only as a fresh effort.

- The Claude Agent SDK and any API-key runtime (C1).
- A scheduler serving several projects at once (OPEN-3 default; a fresh effort if it is overturned).
- Containers for worker sessions (deferred; experiment-job isolation is reconsidered only if a prototype shows a need).
- A GitHub Issues mirror of the ticket graph (optional, one-way, after M5 at the earliest).
- An external verifier backend (the `codex` CLI): the owner decided verdicts are Claude-only unless they opt in per step ([OPEN-6 Verifier backends and order](issues/18-open-6-verifier-backends.md)), so its invocation shape is not on this map.
- Mirror trees or backends for other CLIs in the first version (Section 14).
- Submitting anything anywhere; the harness stops at a reviewed draft.
- A GUI beyond the local dashboard; `status` and REPORT.md remain the views that work without it.
- Initializing this directory as a git repository and the harness package layout itself: that is M0 execution, written as tracer-bullet tickets once this map is done.
